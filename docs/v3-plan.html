PhysTutorBench v3 — Implementation Plan: The Validity-Bridge Study

A preregisterable protocol to test whether any automated tutoring-quality proxy predicts measured physics learning — and a phased roadmap that sequences the rest of the research program behind it.

Author: chaoticcuriosity-io  ·  Status: implementation plan (draft)  ·  Builds on: v1 report + v2 methodology  ·  Direction: #1 (keystone) of the v2 roadmap
The one-sentence study

Recruit real introductory-physics learners, randomize them across a wide gradient of LLM tutors and a control, measure conceptual learning gain with a validated inventory, and ask: do the cheap automated scores we (and every prior benchmark) compute actually predict that learning? If yes, automated evaluation is licensed and the field can scale; if no, the entire LLM-judged-process paradigm — v1 included — is measuring a proxy of unknown worth. This plan specifies the design, the two distinct "bridge" estimators (and why one is well-powered and one is hard), the prerequisites that must be built first, the statistics and decision gates, a worked mechanics/FCI instantiation, and how this single study unlocks the other nine directions.

1. Why this is the keystone

The v2 critique established that no existing LLM-tutoring benchmark — MathDial, CIMA, the AI Teacher Test, TSCC, Bridge, or even SOTA MathTutorBench (v2 §2d) — validates its scores against real student learning. They all score process. v1 did too. So the field has been optimizing proxies no one has shown to predict the outcome that matters. The bridge study is the experiment that either grounds that entire enterprise or refutes it. Until it exists, every leaderboard number (ours included) is uninterpretable as evidence about teaching. Everything else in the roadmap (§8) is more valuable after this anchor.

2. Study design

2.1 Core logic

To estimate whether automated scores predict learning, we need variance in tutoring quality paired with both a measured learning gain and an automated score. The design therefore deliberately spans a wide quality gradient of tutors and captures, for every real tutoring session, the transcript that the student actually experienced — so the same session can be scored both ways.

2.2 Conditions (the quality gradient)

K ≈ 10–16 tutor conditions chosen to span bad → expert, so the bridge has range to detect:

  • Anchored foils (reusing v1's discriminant-validity profiles): an answer-dumper, a confidently-wrong-physics tutor, a pseudo-Socratic tutor, and an expert-prompted tutor. These guarantee spread and double as a discriminant-validity check.
  • Real models × prompt variants: several base LLMs (local + frontier) crossed with prompt regimes (terse vs. scaffolding-forced vs. unconstrained).
  • Control(s): no-tutor (read a standard text for matched time) and, ideally, a human-tutor reference arm to calibrate the effect-size ceiling (human tutoring d≈0.79 — VanLehn 2011).

2.3 Participants & assignment

Real intro-physics learners (course-embedded or recruited via a screened pool), randomly assigned to one tutor condition, stratified by pre-test score and scientific-reasoning ability (both confound normalized gain — Coletta & Phillips 2005). Pre-register the target N (see §4).

2.4 Procedure (per participant)

  consent → pretest (validated inventory + reasoning test + covariates)
         → tutoring session(s) on the target concept cluster(s)   [transcript logged]
         → immediate posttest (parallel form)
         → delayed posttest (~2–4 weeks, durability)

Sessions are time-boxed and focused on a small set of misconception clusters so pre/post items map tightly to what was tutored. Every transcript is stored for Tier-P scoring (§3).

3. Measures & the two bridges

3.1 Tier G — the learning criterion (ground truth)

  • Instrument: a validated concept inventory (e.g., FCI/FMCE for mechanics — Hestenes 1992), used as multi-item subscales, never single items (item-correctness ≠ understanding — [5]).
  • Primary outcome: normalized gain ⟨g⟩ (Hake 1998) and Cohen's d, with IRT/latent-trait scoring to handle the ~25% of answers that flip on retest with no learning ([6]).
  • Covariates: pre-score and scientific-reasoning ability, modeled explicitly (they confound g — [7]).
  • Durability: delayed post-test as a secondary outcome.

3.2 Tier P — the automated scores (the candidate proxies)

  • Process scores on the real transcripts: the v2 behaviorally-anchored, ICAP-grounded rubric (v2 §4.2), applied by a human-calibrated judge or a trained domain reward model (cf. MathTutorBench — [25]), with the bias audit from v2 §3.6.
  • Fully-automated pipeline score: the v1/v2-style run with human-validated simulated students (Phase 0) — the cheap pipeline whose validity we ultimately want to certify.

3.3 The two bridges (the crux)

BridgeUnit / estimatorPowerWhat it licenses
B1 — Rubric-on-real-sessionsEach real student's transcript process-score ↔ that student's measured gain; mixed-effects with random effects for tutor, student, item (N = hundreds)Well-powered (large N, within-condition variance)That the rubric/judge applied to a real session tracks learning — i.e., the scoring instrument is a valid within-study proxy.
B2 — Automated-pipeline-vs-realityCondition-level fully-automated score (simulated students) ↔ condition mean real gain (K data points)Hard (K is small → wide CI on r)The strong claim: that the cheap, no-real-students pipeline predicts real learning and can replace it.
Design consequence. Lead with B1 — it is properly powered and answers "does our scoring track learning at all?" B2 (the holy grail of replacing real students) is bounded by the number of conditions K; a single site can rarely get K large enough for a tight correlation, so B2 should be framed as a multi-site / meta-analytic accumulation across studies that each contribute conditions to a shared, contamination-controlled bank (§8, direction #10). Pretending K=12 dots settle B2 would repeat v1's overreach.

4. Hypotheses, power & decision gates

Preregistered research questions

  • RQ1 (manipulation works): Do LLM tutors produce conceptual gains above the no-tutor control? (Calibrate expectations to d≈0.4–0.8, not "2-sigma" — [8].)
  • RQ2 (B1 bridge): Does the transcript process-score predict student-level gain, controlling for covariates and condition? Which dimensions carry the prediction?
  • RQ3 (B2 bridge): Does the fully-automated pipeline score predict condition-level real gain?
  • RQ4 (discriminant/known-ordering): Do the anchored foils rank as expected (expert > pseudo-Socratic > answer-dumper > wrong-physics) on both tiers?

Analysis

Mixed-effects models (students nested in conditions; crossed random effects for item and scenario), covariate-adjusted; report standardized effects with CIs; correct for multiple comparisons across dimensions/topics; estimate run-to-run variance by repeating Tier-P generations at the intended temperature. All hypotheses, models, exclusions, and thresholds preregistered before data collection (v2 §4.4 template).

Illustrative power (to be finalized by formal analysis + pilot)

  • RQ1: detecting d=0.5 at 80% power ≈ 64 students/arm; inventory measurement noise ([6]) inflates this — budget accordingly.
  • B1: a student-level correlation of r=0.3 at 80% power needs ≈ 85 paired observations — easily met if the RCT is adequately powered for RQ1; aim higher for a tight CI.
  • B2: with K=12 conditions, power to detect r=0.5 is only ≈ 40–50% — explicitly underpowered; treat B2 as accumulation, not a one-shot test.
GATE G1 Go/no-go (preregistered): declare a usable proxy only if B1 shows the process-score predicts gain at r ≥ 0.5 (or a preregistered equivalent effect) with the bias audit passed. If B1 fails, the field cannot use process scores as learning evidence — a major, publishable negative result that reorients everyone (including us) toward Tier-G or better proxies.

6. Ethics, equity & reproducibility

  • IRB & consent for real-learner data; data governance and de-identification plan.
  • Harm protocol: a real student may be taught wrong physics by a foil/weak tutor — require a debrief + correct-instruction remediation after post-testing, and a real-time wrong-physics guardrail option (direction #6).
  • Equity: pre-register subgroup analyses (prior attainment, reasoning ability, language, demographics) and report differential effectiveness — gain confounds with incoming ability ([7]), so equity is a first-class outcome.
  • Reproducibility: versioned models/prompts/seeds; preregistration; open release of the item bank (held-out splits + canaries), transcripts (consented), rubric, and analysis code.

7. Worked instantiation (mechanics / FCI)

  • Domain: Newtonian mechanics; 3–4 misconception clusters (e.g., Newton's third law, motion-requires-force, gravitation) drawn from the FCI/FMCE.
  • Inventory: FCI subscales for those clusters, parallel pre/post forms; Lawson reasoning test as covariate.
  • Conditions: K=12 — 4 anchored foils + 6 model×prompt variants + no-tutor control + (if feasible) a human-tutor arm.
  • Sessions: ~30 min focused tutoring per cluster.
  • Sample: target ≈ 60–90/arm for RQ1 → several hundred students total (single large course or multi-section / online pool).
  • Tier-P: v2 BARS rubric scored by a Phase-0-calibrated reward model on the real transcripts (B1), plus the fully-automated simulated-student pipeline per condition (B2).
  • Local recipe carry-over: the existing run_local_eval.py / scoring stack instantiates the Tier-P side; the new build is the Tier-G RCT apparatus and the Phase-0 calibration.

10. Milestones & deliverables

  1. M0 (Phase 0): validated item bank, validated simulated student, calibrated judge/reward model — with the §5 acceptance gates met; preregistration filed.
  2. M1 (pilot): small pilot to finalize power, session length, and item parallelism; cognitive-interview report.
  3. M2 (data collection): RCT run; transcripts + pre/post/delayed scores collected.
  4. M3 (analysis): B1 (+ B2 contribution), discriminant-ordering check, equity analysis; Gate G1 decision.
  5. M4 (release): paper + open item bank, transcripts (consented), rubric, reward model, and analysis code — and, if G1✓, the first bridge-validated leaderboard.
The payoff. Whichever way Gate G1 resolves, the field gains its first answer to the question every LLM-tutoring benchmark has so far assumed: do these scores mean anything about learning? That answer is the foundation the other nine directions build on.
